# 待办插件 · 设计规格 v1.0

> 状态：**设计定稿，未实现** · 2026-11-25
> 插件位置（计划）：`deepseek-plugins/todo/` · 包名：`@local/todo` · 面板名：待办 / Tasks

---

## 1. 一句话

一个常驻 DSH 左侧栏的**私人待办看板**：三列（待办 / 进行中 / 已完成）、拖拽即状态、数据只落在本机 JSON 文件里，Agent 完全不可见。

## 2. 定位与边界

### 2.1 目标

- 记录"我自己的"待办，不进入任何会话上下文。
- 打开即用：侧栏一键进入，顶部一行快速录入。
- 一屏看完三列状态，拖拽改变状态与顺序。
- 数据可备份、可读、可迁移；刷新/重启/换浏览器不丢。
- 到期有节制地提醒：只有带具体时间的任务才打扰。

### 2.2 非目标（v1 明确不做）

- 不做 Agent 工具、系统提示词片段、会话日志写入；模型看不见这份数据。
- 不做子任务、协作、多人共享、云同步。
- 不做浏览器系统通知、声音；不做关闭期间漏报的补发弹窗。
- 不做标签颜色、自定义字段、甘特/日历视图。
- 不做批量多选操作（"归档全部已完成"除外）。

## 3. 入口与导航

| 入口 | 行为 |
|---|---|
| 侧栏图标（`sidebar.panellist`） | 图标 + 角标；点击切到待办面板。顺序排在现有面板之后（`order: 30`）。 |
| 主区域页面（`main` 键控槽，key = `todo`） | 三列看板；全局页面，不绑定会话。 |
| `/todo` 客户端命令 | 打开面板并把焦点放进快速添加框。 |
| 侧栏角标 | 未完成数（待办 + 进行中）；存在逾期时转为警示色。图标格较窄，若裁切则降级为圆点（见 §18）。 |

不注册全局快捷键（避免占用键位；`/todo` 足够）。

## 4. 数据模型

### 4.1 记录

```ts
type Todo = {
  id: string                 // 本地唯一，`<base36时间>-<8位随机>`
  title: string              // 去首尾空白，1..200
  note: string               // 纯文本，0..2000，折叠展示
  status: 'todo' | 'doing' | 'done'
  priority: 'high' | 'medium' | 'low' | null
  tags: string[]             // ≤6 个，每个 ≤24 字，去重（比较时忽略大小写）
  dueAt: number | null       // epoch ms；日期型归一化为当天 23:59:00.000 本地时间
  dueHasTime: boolean        // false = 只有日期
  repeat: null | 'daily' | 'weekdays' | 'weekly' | 'monthly'
  order: number              // 仅同列内比较；每次插入或拖拽后该列重排为 0..n-1
  seriesId: string | null    // 重复任务同一条链
  spawnedFrom: string | null // 由哪一条完成后自动生成
  createdAt: number
  updatedAt: number
  completedAt: number | null
  archivedAt: number | null
  remindedAt: number | null  // 已弹过提醒的时间，防重复打扰
}
```

### 4.2 不变量（Host 侧强校验）

1. `repeat !== null` 必须有 `dueAt`；否则拒绝（`repeat-requires-date`）。
2. `dueHasTime === false` 时 `dueAt` 归一化为本地当天 23:59:00.000。
3. `status === 'done'` 必须有 `completedAt`；取消完成时清空。
4. `archivedAt !== null` 的项不出现在看板，只在归档视图。
5. `title` 去空白后不能为空；`tags` 去空白、去重、按原顺序。
6. `seriesId` 只存在于重复任务；`spawnedFrom` 只存在于自动生成的实例。

### 4.3 派生状态

- `overdue`：`!done && !archived && dueAt !== null && dueAt < now`
- `today`：`!done && !archived && dueAt` 落在本地今天
- `badge`：`todo + doing` 的数量（不受筛选影响）
- 相对时间文案：今天 18:00 / 明天 / 昨天 / 逾期 2 天 / 3 月 5 日

## 5. 持久化与并发

- **文件**：`$DSH_HOME/todo/todos.json`（`DSH_HOME` 缺省 `~/.dsh`）。
- **写入**：临时文件 + `rename` 原子替换；写前对破坏性操作（归档全部、删除、重排）生成快照到 `$DSH_HOME/todo/backups/`，保留最近 10 份（可配置）。
- **文档结构**：

```json
{
  "version": 1,
  "revision": 42,
  "updatedAt": 1730000000000,
  "items": [],
  "settings": {}
}
```

- **损坏处理**：JSON 解析失败时把原文件改名为 `todos.corrupt-<时间戳>.json` 保留证据，再以空文档启动；不静默覆盖。
- **版本**：`version > 1` 时拒绝写入并提示（防止旧插件清空新数据）；`version < 1` 或缺省时尽力归一化。
- **并发**：每次变更带 `expectedRevision`；不匹配返回 `409 stale-revision` 与当前文档，客户端整体刷新并提示"已在别处更新"。单窗口下等价于顺序写入。
- **性能**：个人规模（数千条内）整文档读写足够；不做逐条文件布局。

## 6. Host API

Host 半注册两条 exact 路由，均先过 `ctx.connection.requestRejection` 信任围栏，仅接受同源已认证请求。

### 6.1 路由

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/todo/state` | 返回 `{ state, config }`（config 为只读的下发配置：提醒提前量、完成列渲染上限） |
| POST | `/todo/action` | `{ action, payload, expectedRevision }` → `{ state, notice?, error? }`；`Content-Type: application/json`，body ≤ 512 KB |

### 6.2 动作

| action | payload | 结果/说明 |
|---|---|---|
| `item/add` | `{title, status?, dueAt?, dueHasTime?, priority?, tags?, note?}` | 追加到待办列顶部；返回 `id` |
| `item/update` | `{id, ...可改字段}` | 字段级更新；改 `dueAt` 时同步重算 `dueHasTime` |
| `item/status` | `{id, status}` | 拖拽跨列；进入 `done` 时走完成逻辑（§9.3） |
| `item/complete` | `{id}` | 显式完成，等价 `status: done` |
| `item/uncomplete` | `{id}` | 回到 `todo`；按 §9.3 决定是否撤回自动生成的下一次 |
| `item/reorder` | `{id, beforeId?, afterId?, toStatus?}` | 相对定位（不下发整列顺序）；可同时换列 |
| `item/archive` | `{id}` | 仅已完成项；写快照 |
| `item/unarchive` | `{id}` | 回已完成列 |
| `item/remove` | `{id}` | 永久删除；写快照；客户端需二次确认 |
| `items/archiveDone` | `{}` | 归档全部已完成；写快照 |
| `items/rerank` | `{by: 'priority' \| 'due'}` | 一次性重写各列 order（§9.5） |
| `settings/update` | `{reminderLeadMinutes?, donePreviewLimit?}` | 仅允许白名单字段 |

### 6.3 错误码

`invalid-title` `invalid-date` `repeat-requires-date` `item-not-found` `invalid-order` `invalid-status` `stale-revision` `unknown-action` `invalid-action` `body-too-large` `content-type-required` `action-failed`

错误响应带当前 `state`，客户端据此对齐界面，不进入"脏状态"。

## 7. 客户端数据流

- 单例 store + `useSyncExternalStore`；快照 `{ status: 'loading' | 'ready' | 'error', state, config }`。
- 面板首次打开时拉取；之后所有变更走 action，并**以服务端返回的 state 为准**（乐观更新仅用于拖拽的即时反馈，失败即回滚）。
- 跨窗口：收到 `409` 后整体替换并 toast。
- 页面可见性恢复（`visibilitychange`）时若距上次同步超过 60 秒则重拉。
- 提醒定时器：30 秒 tick，仅当文档处于可见状态时推进；`prefers-reduced-motion` 不影响功能。

## 8. 页面规格

### 8.1 整体布局

```
页面（透明底，继承宿主主题）
├─ 头部：标题 + 统计 · 搜索 · 筛选 · 排序 · 新建
├─ 快速添加条（整行）
├─ 筛选条：日期域 chips + 标签 chips
└─ 三列看板（或归档视图）
```

- 内容最大宽度 1280px，居中；左右留白 24px（窄屏 16px）。
- 页面顶部预留 `--dsh-frame-top-clearance`（与其他全局页一致，避免压住窗口标题区）。

### 8.2 头部

- 标题"待办"；副标题一行统计：`12 项未完成 · 3 项今天 · 1 项逾期`（逾期时用警示色，其余用次级文本）。
- 右侧操作：搜索框（可折叠为图标）、筛选、排序菜单、`＋ 新建`（打开快速添加并聚焦）。
- 头部随内容滚动时保持粘性（sticky），高度 56px；滚动后压缩为 48px 并隐藏副标题。

### 8.3 快速添加

- 占位文案：`写点什么，回车保存…`
- 仅标题（v1 不做行内语法）；回车保存，`Esc` 清空并失焦，`Shift+Enter` 不换行（单行输入）。
- 新条目：`status: todo`，`order` 取当前待办列最小值 −1（顶部），`priority: null`，无日期无标签。
- 保存后保持在输入框，允许连续录入；右上角出现 3 秒的"已添加 · 撤销"轻提示。

### 8.4 筛选与搜索

- 日期域：全部 / 今天 / 本周（周一至周日）/ 逾期 / 无日期；单选。
- 标签：多选，OR 语义；列出带数量的标签；选中的标签 chip 可单个清除。
- 搜索：标题 + 备注子串匹配，忽略大小写，150ms 防抖；`/` 聚焦，`Esc` 清空。
- 视图切换：`看板 / 已归档`（分段控件，位于筛选条右端）。
- 所有筛选组合生效；列头数字显示"当前筛选下"的数量，顶部统计始终是全局值。
- 筛选不持久化（刷新回到全部）。

### 8.5 三列与卡片

- 列：待办 / 进行中 / 已完成；列头 = 状态字形 + 名称 + 计数 + 列内"＋"（inline 新增到该列，默认状态对应）。
- 完成列按 `completedAt` 倒序；待办/进行中按 `order` 升序。
- 完成列默认最多渲染 50 条，底部"显示更多"；不影响数据。
- 卡片结构（自上而下）：
  1. 左侧 2px 优先级竖条（高=实色全长；中=40% 高度居中；低/无=无）。
  2. 标题：两行截断；已完成加删除线并使用次级文本色。
  3. 元信息一行：日期（逾期/今天用警示色与文字"逾期 N 天"）· 优先级文字 · 标签 `#工作` · 重复字形 · 备注指示点。
  4. 悬停：显示"完成 / 编辑 / 归档（仅已完成）"三个图标按钮。
- 卡片不使用投影；1px 边框 + 8px 圆角；悬停边框对比度提升；拖拽抬起时允许轻微投影。
- 卡片高度自适应（标题 1–2 行）；同列间距 8px。

### 8.6 就地编辑

- 点击卡片标题区域或按 `Enter` 展开编辑区（不弹对话框）。
- 编辑字段：标题（单行）、备注（多行，3 行起）、截止日期 + 时间开关、优先级（四段选择）、标签（输入 + 已有标签建议）、重复（无 / 每天 / 每个工作日 / 每周 / 每月，需有截止日期才可用）、状态、归档/删除。
- 保存策略：字段失焦即保存（`item/update`），`Esc` 收起，`Ctrl/Cmd+Enter` 立即收起。
- 校验失败就地显示一行错误（如"重复任务需要截止日期"），不关闭编辑区。
- 编辑区展开时卡片仍留在列内，下方的卡片下移；不做浮层，避免遮挡拖拽目标。

### 8.7 已完成与归档

- 已完成卡片：勾选可取消完成（回到待办），"归档"移出看板。
- 列头提供"归档全部"，需确认，并写快照。
- 已归档视图：列表（标题、完成时间、归档时间、标签），操作"恢复"（回已完成列）与"永久删除"（二次确认）。

### 8.8 空态与加载态

- 全空：`还没有待办。在上面输入第一条，回车即可保存。` 并自动聚焦输入框（此时不渲染三列空看板）。
- 列空：待办"空着也挺好"；进行中"把卡片拖到这里，表示正在做"；已完成"完成的会落在这里"。
- 筛选无结果：`没有符合当前筛选的待办。` + `清除筛选`。
- 首屏加载：三列骨架（每列 2 张灰块），不闪白。
- 读取失败：说明原因 + `重试`，保留上次成功快照可用。

### 8.9 响应式

| 宽度 | 布局 |
|---|---|
| ≥ 1100px | 三列并排，最大宽 1280px，列间距 16px |
| 768–1100px | 三列横向滚动 + `scroll-snap`，列最小宽 280px |
| < 768px | 纵向堆叠（待办→进行中→已完成），列头 sticky；卡片编辑全宽；拖拽仍可用，另在编辑区提供"移动到…"菜单作为触屏后备 |

## 9. 交互规格

### 9.1 鼠标与拖拽

- 指针事件自绘拖拽（不用 HTML5 DnD）：按下 4px 阈值后抬起，显示插入指示线；拖到另一列即改状态。
- 拖拽中自动滚动列容器；`Esc` 取消拖拽并复原。
- 拖入"已完成"等同完成（触发重复生成）；从"已完成"拖出等同取消完成。
- 删除不做拖拽手势。

### 9.2 键盘

| 键 | 作用 |
|---|---|
| `/` | 聚焦搜索 |
| `c` | 聚焦快速添加 |
| `Enter`（卡片聚焦） | 展开编辑 |
| `x` | 完成 / 取消完成 |
| `Alt+↑/↓` | 列内上移 / 下移 |
| `Alt+←/→` | 切到上一 / 下一状态列 |
| `Esc` | 收起编辑 / 清空搜索 / 取消拖拽（按上下文优先级） |
| `Delete` | 删除当前聚焦项（需确认） |

- 所有交互元素可 Tab 到达；卡片为单一 tab stop（`role="listitem"` + `tabindex="0"`），内部按钮在展开后才进入 tab 序列。

### 9.3 完成与重复生成

- 完成：置 `status='done'`，写 `completedAt`，卡片移到完成列顶部（按时间倒序显示）。
- 非重复任务：仅此一步。
- 重复任务（`repeat !== null`）：
  1. 从被完成实例的 `dueAt` 起，按规则加一个周期：`daily` +1 天；`weekdays` 下一个周一至周五；`weekly` +7 天；`monthly` 同"几号"，超出当月天数时收敛到月末。
  2. 若结果 ≤ 当前时间，继续累加，直到严格未来。
  3. 生成新实例：同标题/备注/标签/优先级/重复规则/`seriesId`，`dueAt` = 下一次，`dueHasTime` 继承，`status='todo'`，`spawnedFrom` = 被完成实例 id，置于待办列顶部。
  4. 返回 `notice: { kind: 'repeatSpawned', id, dueAt }`，客户端 toast `已生成下一次：明天 09:00`，带 8 秒内"撤销"。
- 取消完成：
  - 若由它自动生成的下一次仍存在、`status==='todo'`、且从未被编辑（`updatedAt === createdAt`），则一并删除；
  - 否则保留，toast 说明"下一次已保留"。
- 编辑重复任务的截止日期只影响当前实例，不改变同系列其他实例。

### 9.4 删除与确认

- 看板删除 = 永久删除，必须先确认（标题写进确认文案）。
- 归档视图的"永久删除"同样二次确认。
- 删除、归档全部、重排前各写一份快照。

### 9.5 排序

- 列内手动顺序是唯一真相；拖拽即时写 `order`。
- 排序菜单：`按优先级重排`（高→中→低→无）、`按截止日重排`（近→远，无日期最后），均为一次性操作，重排对象是全部未完成项（不受当前筛选影响）；重排后不再提供撤销，可继续用拖拽调整。
- 新条目进入待办列顶部；自动生成的重复实例同样置顶。

## 10. 到期提醒与角标

- **仅应用打开时提醒**：页面可见时每 30 秒检查；页面隐藏时不推进，恢复可见时补一次检查。
- 触发条件：`!done && !archived && dueHasTime && dueAt - reminderLeadMinutes*60000 <= now && remindedAt == null`。
- 触发后：写 `remindedAt`（`item/update`），在 `shell.overlay` 显示应用内 toast：`「交周报」18:00 到期`，操作 `打开`（切到待办并高亮该项）；8 秒自动消失。
- 会话开始前就已过期的项：不弹窗，仅以"逾期"样式与角标呈现（符合"不补发"的决定）。
- 只有日期的任务不弹窗（当天 23:59 前都算今天），靠列表与角标提示。
- 角标：未完成总数；存在逾期时改用警示色；`>99` 显示 `99+`；角标 `aria-hidden`，数量变化由页面 `aria-live` 播报。
- 提醒提前量可配置（默认 0 分钟）。

## 11. 视觉方向

### 11.1 隐喻：三只浅托盘

看板不是"三列卡片墙"，而是一张工作台上的三只浅托盘：三列共用一条细线网格，列头像架签（小字形 + 名称 + 数字），卡片是平放的纸条，没有投影、没有渐变、没有彩色标签。全页只有一个视觉重音：**今天/逾期**。

### 11.2 颜色（全部走主题别名令牌）

| 角色 | 令牌角色（实现时以 `Theme.listTokens` 为准） |
|---|---|
| 页面底 | 透明（继承 shell / 玻璃主题），不铺自己的背景层 |
| 卡片面 | 一级抬高面；悬停时提升一档 |
| 边框 | 细边框；悬停/聚焦时提升对比 |
| 文本 | 主 / 次 / 弱三级 |
| 强调 | 仅用于今天与逾期（警示角色） |
| 成功 | 完成勾选与完成列的轻微提示 |

- 禁止：自造品牌色、彩虹标签、按优先级整卡染色。
- 优先级只用左侧竖条（形态编码）与元信息文字（"高/中/低"），不依赖颜色。

### 11.3 字体与数字

- 继承宿主 UI 字族与 `--dsh-content-font-size`；不引入外部字体。
- 标题 13/20，元信息 11.5/16，列头 12/16，页面标题 22/28。
- 计数、日期、时间使用 `font-variant-numeric: tabular-nums`。
- 全部中文/英文标签用句首大写或普通中文，不用全大写、不用装饰性引号。

### 11.4 尺寸与间距

- 8px 基准栅格；卡片内边距 10×12；卡片间距 8；列间距 16；页面左右 24（窄屏 16）。
- 圆角与宿主卡片一致（实现时对齐 8px 左右）；输入框与按钮沿用宿主控件高度。
- 点击目标 ≥ 28×28；图标按钮 28px 命中区、16px 字形。

### 11.5 动效

- 只回应操作：展开 140ms、拖拽抬起 120ms、toast 进出 160ms，`ease-out`。
- 不做入场逐卡淡入、不做 hover 位移。
- `prefers-reduced-motion` 下移除全部过渡，保留状态变化。

### 11.6 玻璃主题兼容

- 页面与列容器不得设置不透明背景色；卡片面使用主题抬高色并允许玻璃层透出。
- 边框与分隔线在半透明背景上仍需可辨（必要时用主题的 hairline 角色）。
- 深色与浅色主题都要实测（当前 profile 为 Catppuccin Frappe 深色 + 玻璃）。

## 12. 可访问性

- 列与卡片使用列表语义；列头是 `aria-labelledby` 的目标。
- 筛选 chip 使用 `aria-pressed`；视图切换用 `role="tablist"` 或分段按钮并标注选中态。
- 提醒 toast：`role="status"`；删除确认对话框：焦点陷阱、`Esc` 关闭、焦点归还触发按钮。
- 颜色不是唯一编码：逾期有"逾期 N 天"文字，优先级有文字，重复有字形 + 元信息"重复"。
- 键盘完成全部核心操作（§9.2）；拖拽有键盘等价。
- 对比度满足 WCAG AA（正文与元信息分别校验）。

## 13. 国际化

- 字典命名空间 `todo`，提供 `zh` / `en`（与现有本地插件一致，`ctx.locale.register`）。
- 面板名、按钮、空态、错误码文案、相对时间（今天/明天/昨天/N 天前）全部走字典。
- 日期与时间用 `Intl.DateTimeFormat`，跟随 `ctx.locale` 当前语言。
- 文案原则：动词开头、说清结果（"归档"→"已归档 7 项"），错误不道歉、说明如何修复。

## 18. 风险与待验证

1. **角标裁切**：侧栏图标格 16px，数字角标可能被裁切；M1 实测，退化方案为小圆点（逾期时显示）。`label` 无法携带计数，数量只能靠角标与页面统计。
2. **`/todo` 命令接入**：需确认 `ctx.commandUi` 的 action 注册签名与可用性（任何会话下均可执行）；不可用则退化为"仅侧栏入口 + 说明"。
3. **玻璃主题对比度**：半透明层叠下 hairline 边框与弱文本可能过淡，M2 需在真实主题中截图校对。
4. **拖拽手感**：指针事件自绘需处理滚动容器自动滚动与触屏；Electron 下需实测。
5. **月度重复边界**：31 号在 2 月的收敛规则需测试覆盖。
6. **多浏览器并发**：revision 冲突策略为"刷新覆盖本地"，需确保不丢用户正在编辑的草稿（编辑区内容在冲突时保留为本地草稿并提示）。

## 19. 明确不做

子任务、Agent 工具与会话耦合、多端实时同步、协作与共享、提醒补发、系统级通知、标签颜色、批量多选、日历/甘特视图、导入导出（可作为后续版本）、主题自定义。
